# Presentation Page

Each discovered presentation gets its own page, accessible from the overview or via a direct URL.

## URL Structure

Presentations are served under the configured `routeBasePath`. The URL slug is derived from the file path relative to the `path` directory:

| File | URL |
|---|---|
| `slidev/intro.md` | `/presentations/intro` |
| `slidev/tutorials/getting-started.md` | `/presentations/tutorials/getting-started` |
| `slidev/advanced/deep-dive.md` | `/presentations/advanced/deep-dive` |

---

## How It Works

The presentation page renders the compiled Slidev output inside an **iframe**. During `docusaurus build`, the plugin invokes `slidev build` for each presentation, producing a static HTML/JS bundle. That bundle is copied into the Docusaurus build output and loaded in the iframe at runtime.

---

## Page Layout

The presentation page includes:

1. **Top-right action bar** — contains the Presenter View link, PDF download button (when enabled), and fullscreen toggle.
2. **Iframe** — the Slidev presentation, scaled to fill the available viewport.
3. **Resume bar** — appears at the bottom when the user has a saved viewing position for this presentation.
4. **Playlist navigation bar** — appears at the bottom when the presentation is part of a playlist.
5. **Back link** — returns to the overview page.

---

## Presenter View

The action bar in the top-right corner contains a **Presenter View** link that opens the Slidev presenter mode in a new browser tab. The presenter view displays speaker notes alongside the current slide and is useful when presenting with two screens.

- In **production**, the link targets the presenter mode URL of the statically built output.
- In **dev mode**, the link targets the local Slidev dev server's presenter URL (e.g. `http://localhost:3030/presenter/`), so it is only functional when that server is running.

---

## PDF Download

When the `download` plugin option is set to `true`, a **PDF** button appears in the top-right action bar alongside the Presenter View link.

```ts title="docusaurus.config.ts"
[
  "slidesaurus",
  {
    download: true,
  },
]
```

The PDF is generated by `slidev export` at build time as part of each presentation's build step. This requires [Playwright](https://playwright.dev/) to be installed in the project:

```bash
npx playwright install chromium
```

Clicking the PDF button downloads the pre-generated file directly — no server-side processing occurs at runtime.

:::tip
PDF generation adds time to your build. If only some presentations need a downloadable PDF, you can keep `download: false` globally and override it per-presentation in the future via frontmatter when that option becomes available.
:::

## Resume Bar

If a user previously visited this presentation and left mid-way through, a bar appears at the **bottom of the page** on their next visit. The bar offers two actions:

- **Resume from slide N** — jumps the iframe directly to the slide where the user stopped.
- **Start from beginning** — dismisses the bar and starts at slide 1.

The last-viewed slide number is stored in `localStorage` using the key `slidev-resume-{id}`, where `{id}` is the presentation's unique identifier derived from its file path. The value is updated continuously as the user navigates between slides.

Dismissing the bar (by starting from the beginning or completing the presentation) clears the stored position so the bar does not reappear on subsequent visits.

---

## Playlist Navigation Bar

When a presentation is part of a playlist (defined via the `playlist` frontmatter field — see [Frontmatter Reference](./frontmatter.md)), a navigation bar appears at the **bottom of the page**. It shows:

- The **playlist name**.
- The **current position** within the playlist (e.g. `2 / 5`).
- A **← previous** link to the preceding presentation in the playlist.
- A **next →** link to the following presentation in the playlist.

Previous and next links are disabled (and visually dimmed) when the user is at the start or end of the playlist.

The playlist bar and the resume bar can appear simultaneously if both conditions are met — they stack vertically.

## SEO Metadata

The presentation page automatically injects structured metadata into the document `<head>`:

### Open Graph Tags

| Tag | Value |
|---|---|
| `og:title` | The presentation's `title` frontmatter field |
| `og:description` | The presentation's `description` frontmatter field |
| `og:url` | The canonical URL of the presentation page |
| `og:image` | The presentation's thumbnail, when available |

### Twitter Card

When a thumbnail is present, the page sets `twitter:card` to `summary_large_image` for a rich preview in Twitter/X link unfurls. Without a thumbnail, it falls back to `summary`.

### JSON-LD Structured Data

A [`LearningResource`](https://schema.org/LearningResource) JSON-LD block is injected to improve discoverability in search engines:

```json
{
  "@context": "https://schema.org",
  "@type": "LearningResource",
  "name": "Advanced TypeScript Patterns",
  "description": "Deep dive into conditional types...",
  "author": { "@type": "Person", "name": "Jane Smith" },
  "url": "https://example.com/presentations/typescript/advanced-patterns",
  "thumbnailUrl": "https://example.com/presentations/typescript/advanced-patterns/thumbnail.png"
}
```

The `author`, `url`, and `thumbnailUrl` fields are omitted from the JSON-LD block when the corresponding frontmatter values are not set.

## Keyboard Navigation

Inside the iframe, standard Slidev keyboard shortcuts work:

| Key | Action |
|---|---|
| `→` / `Space` | Next slide |
| `←` | Previous slide |
| `f` | Toggle fullscreen |
| `o` | Toggle slide overview |
| `d` | Toggle dark mode |

---

## Dev Mode vs Production

### Production (`docusaurus build`)

Full Slidev builds run for every discovered presentation. The iframe loads the compiled static output bundled into the Docusaurus build directory.

### Dev Mode (`docusaurus start`)

In dev mode, the plugin does not run `slidev build`. Instead, if `@slidev/cli` is installed and a `slidev` dev server is detected as running locally, the presentation page embeds the live dev server output in the iframe. This enables hot-reload while authoring slides.

If `@slidev/cli` is **not installed**, the iframe area is replaced by a placeholder message:

> **Slidev CLI Not Installed**
> Install `@slidev/cli` and run `slidev dev <file>` in a separate terminal to preview this presentation in development mode.

:::tip
Run the Slidev dev server in a separate terminal while `docusaurus start` is running:

```bash
npx slidev dev slidev/my-talk.md --port 3030
```

The presentation page will pick up the running server and display the live output.
:::
